# 两插件共享直播截图快捷键（规划草案）

## Goal

为 bella-gif-helper 与 bella-live-clip 增加共享的直播截图快捷键；一次按键等同点击播放器右上角截图按钮，在任一插件中修改后另一插件同步，双装只下载一张图。

## 已确认

- 规划已获准实施；用户于 2026-11-14 明确授权提交并推送两个仓库。
- 两插件都要考虑更新以及同时安装的行为。
- GIF 助手已有直播截图模块，通过共享 DOM 标记实现每个 document 单一截图执行方。
- GIF 助手已有独立的启动快捷键和 GM 偏好存储；新截图快捷键需要与之区分。
- 两插件设置同步必须无感，不显示“与另一插件共享”等说明。
- 设置界面仅增加快捷键设置项，不自行增加说明、开关或恢复默认控件。
- 截图快捷键默认为单键 P（KeyP，无修饰键）。
- 截图快捷键在全屏状态也必须生效；验收覆盖播放器原生全屏、网页全屏、浏览器全屏及活动页内嵌播放器全屏。
- 两插件其他可配置快捷键也允许单键，不再强制 Ctrl / Alt / Meta；仍支持组合键，已有配置和其他快捷键默认值保留。
- 不做跨直播间即时同步；同页两个插件修改截图快捷键后仍须同步并持久化。
- 所有本任务新增或修改的用户可见文案必须逐条先经用户确认，包含标签、占位符、提示、title、错误消息和无障碍名称。未确认不得落地；已有复用文案也在实现前列明，不默认视为已批准。
- 用户强调文案简洁，避免不必要的用户可见文字。

## 实现决策

- 独立 GM 设置键 + 同源缓存，DOM 字符串事件桥接同页插件；启动时按变更版本合并，停用过的插件再次启动时恢复最新可见配置。跨域 iframe 通过验证父子窗口与来源的消息同步。
- 冲突时拒绝重复设置并保留原绑定；三个文案已确认，任何额外文案仍须先确认。
- 优先全屏播放器，然后聚焦的 iframe、最后交互的播放器或最大可见播放器；不截编辑器预览。
- 快捷键所有权与原截图按钮所有权分离，新旧混装继续调用已有相机按钮。

## 暂定验收范围

- [x] 单装任意插件可用，双装按一次仅保存一张 PNG。
- [x] 快捷键与按钮使用相同截图路径和截图时机。
- [x] 任一设置入口修改后另一入口与执行配置保持一致，刷新保留。
- [x] 输入文字、输入法组合、录制快捷键和按住重复触发时不误截。
- [x] 检查两种启动顺序、新旧版本组合、播放器重建、活动页 iframe。
- [x] 单键可触发截图；输入文字与快捷键设置期间不误截。
- [x] 截图默认 P；两插件其他可配置快捷键接受单键，旧组合键继续有效。
- [x] 普通、网页全屏、播放器原生全屏与浏览器全屏均可按键截图；进出全屏后仍有效，相机控件自动隐藏时也可触发。
- [x] 活动页内嵌播放器全屏且焦点在 iframe 时可截图；双装只下载一张，目标为当前全屏播放器。
- [x] 所有新增或修改的用户可见文案有用户明确确认记录，无共享说明文案。

## Out of Scope

- GIF 编解码、录制、回溯算法的改动。
- 分发通道调整。
- 将两插件全部偏好设置合并同步。
- 跨直播间即时同步，不为此建立广播或订阅机制。

## 实施方案

- 两个设置入口修改同一个截图快捷键；原启动快捷键独立。使用已确认的标签与录制状态文案，不自行添加禁用或恢复默认功能。
- 按键协调器在每个 document 内只注册一个有效执行方，与原截图模块的所有权分开，兼容旧版先启动。
- 快捷键同步触发已增强的截图按钮（必须确认已有相机标记，不能点击原反馈按钮），复用原捕帧、busy 状态、文件命名与下载路径；按键回调不等待协商再捕帧。
- 全屏目标判定不能依赖截图按钮当前可见；确保键盘入口覆盖播放器所属 document，进出全屏不重复注册。iframe 内的按键和顶层路由避免重复执行；具体通信方式在实现准备阶段验证。
- 配置协议与截图执行协议分离，配置同步不能触发截图。
- 页面桥接 + 各脚本独立持久化 + 同源缓存 + 变更版本去重；不订阅 storage 事件，不即时更新其他直播间。
- 新旧混装只承诺新版能提供快捷键与不重复截图；旧版没有的设置 UI 无法同步显示。两边都升级后提供完整双向设置体验。
- 默认 P 已在浏览器实测，允许修改；不增加清空、禁用或恢复默认控件。

- 冲突提示：`快捷键已被占用`。
